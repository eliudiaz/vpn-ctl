Layer 1: POD LAYER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  
  Pod (EKS Container)
  IP: 172.31.x.x
  
  Creates Packet:
  Source: 172.31.x.x (Pod's own IP)
  Destination: 172.16.70.1 (Vimenca) OR 192.168.100.8 (Organization-Legacy)
  
  ↓ Packet exits pod eth0 interface

Layer 2: NODE LAYER (iptables SNAT Rewrite)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ╔═════════════════════════════════════════════════════════════════════════╗
  ║ VIMENCA PATH: WITH SNAT MASQUERADING                                    ║
  ╚═════════════════════════════════════════════════════════════════════════╝
  
  iptables POSTROUTING evaluation:
  
  Is destination 172.16.70.0/24?
    ✓ YES → SNAT Rule Matches!
    
    Rewrite source IP:
    172.31.x.x → 203.0.113.10 (SNAT Instance)
  
  Packet BEFORE:  Source: 172.31.x.x     → Destination: 172.16.70.1
  Packet AFTER:   Source: 203.0.113.10   → Destination: 172.16.70.1
  
  ⚠️  Vimenca firewall will see 203.0.113.10 as source
  
  ─────────────────────────────────────────────────────────────────────────
  
  ╔═════════════════════════════════════════════════════════════════════════╗
  ║ ORGANIZATION-LEGACY PATH: WITHOUT SNAT MASQUERADING                         ║
  ╚═════════════════════════════════════════════════════════════════════════╝
  
  iptables POSTROUTING evaluation:
  
  Is destination 172.16.70.0/24?       ✗ NO
  Is destination 172.16.65.21/32?      ✗ NO
  Is destination 172.16.82.0/24?       ✗ NO
  Is destination 203.0.113.10/32?      ✗ NO
  
  NO RULES MATCH!
  
  → Packet passes through UNCHANGED
  
  Packet BEFORE:  Source: 172.31.x.x   → Destination: 192.168.100.8
  Packet AFTER:   Source: 172.31.x.x   → Destination: 192.168.100.8
  
  ✅ Original pod IP preserved!
  ⚠️  Legacy firewall will see 172.31.x.x as source
  
  ↓ Packet exits node with either masqueraded or original IP

Layer 3: VPC LAYER (Route Table)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  
  EKS VPC: vpc-0efe6f2c199a72f9a
  Route Table: rtb-0ab7fb95716fe9036
  
  VIMENCA:
    Destination: 172.16.70.0/24  → Transit Gateway ✓
  
  ORGANIZATION-LEGACY:
    Destination: 192.168.100.8/32 → Transit Gateway ✓
  
  ↓ All traffic redirected to TGW

Layer 4: TRANSIT GATEWAY (Routing Hub)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  
  TGW: tgw-0572ce4b80ff7445a (Central Hub)
  
  TGW Route Table Query:
  
  Destination 172.16.70.0/24?
    → Route to vpn-05ea9c12f40b67844 (Vimenca VPN)
  
  Destination 192.168.100.8/32?
    → Route to vpn-028ce4c7f59b83bdd (Organization-Legacy VPN)
  
  ↓ VPN connection selected

Layer 6: CUSTOMER FIREWALL (Verification)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  
  VIMENCA CHECKPOINT:
    Firewall IP: 191.97.106.141
    
    Firewall receives encrypted packet → Decrypts
    
    Checks rule: "Allow EKS to Vimenca"
      Source: 203.0.113.10/32 ✓ MATCH (masqueraded IP)
      Destination: 172.16.70.0/24 ✓ MATCH
      → ACCEPT ✅
  
  ──────────────────────────────────────────────────────────
  
  ORGANIZATION-LEGACY CHECKPOINT:
    Firewall IP: 52.254.86.115
    
    Firewall receives encrypted packet → Decrypts
    
    Checks rule: "Allow EKS Pods to Legacy Databases"
      Source: 172.31.0.0/16 ✓ MATCH (original pod network)
      Destination: 192.168.100.8 ✓ MATCH
      Port: 1433 (MSSQL) ✓ MATCH
      → ACCEPT ✅
  
  ↓ Firewall forwards packet to destination

Layer 7: DESTINATION NETWORK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  
  VIMENCA:
    Server at 172.16.70.1 receives packet
    Server responds
    Response travels BACK through VPN
    iptables REVERSE-NATs: 203.0.113.10 → 172.31.x.x
    Pod receives response from 172.16.70.1 ✅
  
  ORGANIZATION-LEGACY:
    MSSQL Server at 192.168.100.8 receives query
    Server executes query and responds
    Response travels BACK through VPN
    Packet maintains original IPs (no NAT reverse needed)
    Pod receives response from 192.168.100.8 ✅

WHY DIFFERENT APPROACHES?

Vimenca wanted a single static IP (203.0.113.10):
  ✓ Simpler firewall rules (whitelist 1 IP instead of /16)
  ✓ Better for auditing (all traffic appears from same IP)
  ✓ Works with strict firewall policies
  ✗ Requires SNAT instance
  ✗ More complex iptables configuration

Organization-Legacy using original pod IPs (172.31.0.0/16):
  ✓ Simpler architecture (no SNAT needed)
  ✓ Better visibility (can trace back to original pod)
  ✓ Firewall sees actual source
  ✗ Firewall must whitelist /16 CIDR

DEBUGGING CHECKLIST FOR DEVELOPERS

If traffic isn't reaching Vimenca (172.16.70.0/24):
  1. ✓ Check pod has network connectivity: kubectl exec pod -- ping 8.8.8.8
  2. ✓ Check iptables rule is active: iptables -t nat -L POSTROUTING
  3. ✓ Check VPC route exists: aws ec2 describe-route-tables
  4. ✓ Check TGW route exists: aws ec2 search-transit-gateway-routes
  5. ✓ Check VPN tunnel is UP: aws ec2 describe-vpn-connections
  6. ✓ Check Vimenca firewall allows 203.0.113.10
  7. ✓ Check VPN connection state is "available"

If traffic isn't reaching Organization-Legacy (192.168.100.x):
  1. ✓ Check pod has network connectivity: kubectl exec pod -- ping 8.8.8.8
  2. ✓ Check NO iptables rules match 192.168.100.x
  3. ✓ Check VPC route exists for 192.168.100.x/32
  4. ✓ Check TGW route exists for 192.168.100.x/32
  5. ✓ Check VPN tunnel is UP (or will be once firewall configured)
  6. ✓ Check Legacy firewall allows 172.31.0.0/16 to 192.168.100.x:1433
  7. ✓ Check VPN connection state is "available"
