🎯 Overview

This guide provides step-by-step instructions for configuring a Palo Alto Networks Next-Generation Firewall to establish a secure, redundant VPN tunnel connection to Affinity’s AWS Transit Gateway infrastructure.

What You’re Building

Your Network              Affinity Transit Gateway      AWS Network
(172.16.0.0/16)          (Hub & Spoke)                 (VPCs)
      │                         │                           │
      ├─ Tunnel 1 (Primary)────►│                           │
      │  (52.14.x.x:500)        ├─ Route Propagation ─────►│
      │                         │                           │
      ├─ Tunnel 2 (Secondary)──►│                           │
      │  (52.14.y.y:500)        │                           │
      │                         │                           │
      └─ BGP 65000             └─ BGP 64512 (AWS)          │
         (Dynamic Routing)       (Dynamic Routing)         │

Key Benefits

  • ✅ Redundancy: Dual tunnels with automatic failover
  • ✅ Dynamic Routing: BGP learns routes automatically
  • ✅ Encryption: IKEv2 with AES-256, SHA2-256
  • ✅ Low Latency: Direct AWS connectivity
  • ✅ AWS Managed: Transit Gateway handles complexity

Estimated Setup Time: 30-45 minutes

🔐 Tunnel Parameters

Encryption & Authentication Standards

All Palo Alto configurations use these identical parameters:

Parameter Value
IKE Version IKEv2
Phase 1 Encryption AES-256
Phase 1 Integrity SHA2-256
Phase 1 DH Group DH Group 14 (modp4096)
Phase 1 Lifetime 28800 seconds (8 hours)
Phase 2 Encryption AES-256
Phase 2 Integrity SHA2-256
Phase 2 PFS Optional (Recommended)
Phase 2 Lifetime 3600 seconds (1 hour)
DPD Timeout 10 seconds
DPD Action clear

Why These Settings?

  • IKEv2: Modern, more resilient than IKEv1
  • AES-256: FIPS 140-2 approved, strong encryption
  • SHA2-256: Industry standard integrity checking
  • DH Group 14: Balances security and performance
  • DPD: Detects and recovers from tunnel failures automatically

🔧 Step-by-Step Configuration

STEP 1: Open Palo Alto Web Console

  1. Navigate to https://[paloalto-ip]/ or use Panorama
  2. Log in with admin credentials
  3. Navigate to Network → IPSec Crypto

STEP 2: Create IPSec Crypto Profile

  1. Click IPSec Crypto Profiles
  2. Click Add to create new profile
  3. Configure:
    • Name: Affinity-ATG-Profile
    • Encryption: AES-256 (check the box)
    • Authentication: SHA2-256 (check the box)
    • DH Group: Group 14 (check the box)
    • Lifetime (seconds): 3600
  4. Click OK

STEP 3: Create IKE Crypto Profile

  1. Click IKE Crypto Profiles
  2. Click Add to create new profile
  3. Configure:
    • Name: Affinity-ATG-IKE-Profile
    • DH Groups: Group 14 (check the box)
    • Encryption: AES-256 (check the box)
    • Authentication: SHA2-256 (check the box)
    • Lifetime (hours): 8
  4. Click OK

STEP 4: Create IKE Gateway

  1. Navigate to Network → IKE Gateways

  2. Click Add to create new gateway

  3. Configure:

    • Name: Affinity-IKE-Gateway-1
    • Version: IKEv2 only
    • Interface: Your external interface (e.g., ethernet1/1)
    • Peer IP Address: 52.14.X.X (Affinity endpoint)
    • Pre-shared Key: [PSK provided by Affinity] (case-sensitive!)
    • Local IP Address: Your public IP (optional, if static)

  4. Advanced Options:

    • IKE Crypto Profile: Affinity-ATG-IKE-Profile
    • DPD: Enable
    • DPD Interval (seconds): 10

  5. Click OK

  6. Repeat for Gateway 2 with:

    • Name: Affinity-IKE-Gateway-2
    • Peer IP: 52.14.Y.Y
    • PSK: [Second PSK from Affinity]

STEP 5: Create IPSec Tunnel

  1. Navigate to Network → IPSec Tunnels

  2. Click Add to create new tunnel

  3. Configure:

    • Name: Affinity-ATG-Tunnel-1
    • Tunnel Interface: (will be auto-created)
    • Type: Auto Key (IKE)
    • IKE Gateway: Affinity-IKE-Gateway-1
    • IPSec Crypto Profile: Affinity-ATG-Profile

  4. Advanced Options:

    • Enable Fragmentation: Yes
    • Enable Anti-replay: Yes

  5. Click OK

  6. Repeat for Tunnel 2 with:

    • Name: Affinity-ATG-Tunnel-2
    • IKE Gateway: Affinity-IKE-Gateway-2

STEP 6: Configure Tunnel Interface

  1. Navigate to Network → Interfaces
  2. For each IPSec tunnel, configure interface:
    • Name: Select the tunnel (e.g., Affinity-ATG-Tunnel-1)
    • Type: Layer 3
    • IPv4 Address: 169.254.X.2/30 (your side of tunnel 1)
  3. Repeat for Tunnel 2:
    • Interface: Affinity-ATG-Tunnel-2
    • IPv4 Address: 169.254.Y.2/30
  4. Click OK

STEP 7: Create Security Policy

  1. Navigate to Policies → Security

  2. Click Add to create new policy

  3. Configure:

    • Name: VPN-to-Affinity
    • Source Zone: Your LAN zone
    • Destination Zone: Create new zone for tunnel interfaces
    • Source Address: Your network object (e.g., Local-Network)
    • Destination Address: Affinity network object (e.g., Affinity-Network)
    • Application: Any
    • Action: Allow

  4. Options Tab:

    • Enable Logging: On
    • Log at End: Yes

  5. Click OK

  6. Repeat for Tunnel 2:

    • Destination Zone: Same tunnel zone
    • Other settings same

STEP 8: Create Static Routes (If Not Using BGP Initially)

  1. Navigate to Network → Virtual Routers
  2. Select default router, click Static Routes
  3. Click Add to create route:
    • Destination: 10.0.0.0/16 (Affinity CIDR)
    • Next Hop: 169.254.X.1 (Tunnel 1 gateway)
    • Interface: Affinity-ATG-Tunnel-1
    • Metric: 20
  4. Add failover route:
    • Destination: 10.0.0.0/16
    • Next Hop: 169.254.Y.1 (Tunnel 2 gateway)
    • Interface: Affinity-ATG-Tunnel-2
    • Metric: 30
  5. Click OK

STEP 9: Commit Configuration

  1. Click Commit in top right
  2. Confirm changes in review screen
  3. Wait for commit to complete (typically 2-5 minutes)
  4. Monitor Task Manager for completion

🔄 BGP Dynamic Routing

Step 1: Enable BGP

  1. Navigate to Network → Virtual Routers
  2. Select your router, click BGP
  3. Configure:
    • Enable: Yes
    • Local AS Number: Your assigned ASN (e.g., 65000)
    • Router ID: Your firewall’s management IP

Step 2: Configure BGP Peers

  1. Under BGP Peers, click Add
  2. Configure for Tunnel 1:
    • Peer Name: Affinity-BGP-1
    • Peer AS Number: 64512 (AWS ASN)
    • Address Family (IPv4): Enable
    • Peer Address: 169.254.X.1 (AWS side)
    • Local Address: 169.254.X.2 (your side)
    • Keep Alive Interval: 60 seconds
    • Hold Time: 180 seconds
  3. Repeat for Tunnel 2:
    • Peer Name: Affinity-BGP-2
    • Peer Address: 169.254.Y.1
    • Local Address: 169.254.Y.2

Step 3: Configure Route Redistribution

  1. Under Redistribution Rules, click Add
  2. Configure:
    • Name: Affinity-Redistribute
    • Source: Static (to advertise static routes)
    • Destination: BGP
    • Action: Redist
  3. (Optional) Set Route Maps to control which routes advertised

Step 4: Commit BGP Configuration

  1. Click Commit
  2. Verify peer status shows “Established”

✅ Verification Procedures

Verify Tunnel Status

In Web Console:

  1. Navigate to Network → IPSec Tunnels

  2. Check status:

    Affinity-ATG-Tunnel-1: ✓ UP (Phase 2 SAs)
Affinity-ATG-Tunnel-2: ✓ UP (Phase 2 SAs)

Via Command Line (SSH):

show vpn ipsec sa
# Should show both tunnels with SAs established

show vpn ipsec flow tunnel name Affinity-ATG-Tunnel-1
# Check tunnel traffic

Verify BGP Routes

In Web Console:

  1. Navigate to Network → Virtual Routers

  2. Select router, click BGP

  3. Check BGP Peers:

    Affinity-BGP-1: State = Established
Affinity-BGP-2: State = Established

  4. Click Routing Table to see learned routes

Via Command Line:

show routing bgp summary
# Shows peer count and routes

show routing bgp peers
# Detailed peer status

show routing route bgp
# Routes learned from BGP

Test Connectivity

From Palo Alto:

ping host 10.0.0.10
# Should receive responses

ping source 172.16.0.1 host 10.0.0.10
# Test from specific local address

From Affinity Side:

Affinity DevOps will verify: - Tunnel endpoints reachable - BGP routes learned - Traffic passing through

🐛 Troubleshooting

Issue: Tunnel Stays DOWN

Symptoms: Both tunnels show DOWN or “Incompletely negotiated”

Diagnosis:

show vpn ipsec sa
# Check SAs status

show vpn ipsec flow tunnel name Affinity-ATG-Tunnel-1
# Check for errors

debug ike
# Enable IKE debugging (temporary)

Solutions:

  1. Verify PSK Match:
    • Check PSK in Palo Alto matches exactly what Affinity provided
    • PSKs are case-sensitive
    • No extra spaces or characters
  2. Check Security Policy:
    • Ensure security policy allows IPSec traffic
    • Verify policy before deny-all rule
  3. Verify Encryption Settings:
    • Confirm IKEv2 only selected
    • Check crypto profiles match: AES-256, SHA2-256, Group 14
    • Verify lifetimes match specification
  4. Check Interface Configuration:
    • Verify tunnel interface IPs configured: 169.254.X.2/30
    • Confirm external interface allowed for IPSec

Issue: BGP Routes Not Learning

Symptoms: Tunnel UP but no routes in routing table

Diagnosis:

show routing bgp peers
# Check peer status and learned/advertised prefixes

show routing bgp rib
# Check BGP routing information base

show routing route bgp
# Routes actually in routing table

Solutions:

  1. Verify BGP Enabled:
    • Confirm BGP enabled on virtual router
    • Check Local AS number set correctly
  2. Check Peer Configuration:
    • Verify peer IP matches tunnel inside IP
    • Confirm Remote AS = 64512 for AWS
    • Check peer state = “Established”
  3. Review BGP Timers:
    • Keep alive should be ≤ 60 seconds
    • Hold time should be ≥ 180 seconds
  4. Check Route Filters:
    • Verify no import filters rejecting AWS routes
    • Check address family (IPv4) enabled

Issue: Traffic Not Passing

Symptoms: Tunnel UP, routes learned, but no data flow

Diagnosis:

show vpn ipsec flow tunnel name Affinity-ATG-Tunnel-1
# Check if tunnel passing traffic

show statistics zone name <zone-name> detail
# Check zone statistics

debug flow basic
# Enable traffic flow debugging

Solutions:

  1. Verify Security Policy:
    • Confirm policy allows traffic source → destination
    • Check policy is enabled and before any deny rules
    • Verify correct zones specified
  2. Check Routing:
    • Ensure static/BGP routes present in routing table
    • Verify next-hop gateway reachable
    • Check route has correct interface
  3. Enable Logging:
    • Log all VPN traffic temporarily
    • Review logs for accepted/dropped packets
    • Check if traffic matches security policy

🧪 Joint E2E Testing (Phases 3-7)

After device configuration is complete, both Affinity and your DevOps team conduct structured testing via the master protocol: VPN_E2E_TESTING_PROTOCOL.md

This section covers Palo Alto-specific testing procedures for each phase.

Phase 3: IKE/IPSec Tunnel Establishment (Layer 1-2)

Timeline: Immediately after configuration is committed

What happens: Your device initiates IKE; AWS responds; tunnels reach UP state

Your action: Monitor tunnel negotiation

# Real-time tunnel status
show vpn ipsec sa

# Expected output (Phase 1 & 2 statuses):
# tunnel: aws-tunnel-1
#   state: Established (IKE Phase 1 complete)
#   SA entries: 2 (Phase 2 IPSec SA pairs)
#
# tunnel: aws-tunnel-2
#   state: Established
#   SA entries: 2

# Detailed IKE status
show vpn ike sa

# Monitor negotiations in real-time
request vpn ike-sa-query timeout 30

# Verify encryption/transform sets
show vpn ipsec sa detail

Affinity verifies: AWS console shows both tunnels UP (via skill-vpn-connectivity)

Gate 3.1: Both tunnels show Established on both sides

If tunnels stay DOWN after 30 seconds: See Troubleshooting → “Tunnel Stays DOWN”

Phase 4: BGP Route Exchange (Layer 3)

Timeline: 5-15 seconds after tunnels reach UP

What happens: BGP neighbors establish; routes learned automatically

Your action: Monitor BGP neighbor state

# Check BGP neighbors (should show Established)
show routing bgp peers

# Expected output:
# Peer        AS    State      Up/Down  Routes
# 169.254.10.1 64512 Established 00:05:10   3
# 169.254.11.1 64512 Established 00:05:10   3

# View routes learned from BGP
show routing bgp rib routes

# Verify learned routes in main routing table
show routing route bgp

# Check BGP summary
show routing bgp summary

Affinity verifies: AWS Transit Gateway route table contains your CIDRs with state=active

Gate 4.1: BGP neighbors Established; routes appear in both TGW table and your routing table

If routes don’t appear: See Remediation Playbooks → “BGP Routes Not Appearing”

Phase 5: Data Plane Traffic Test (Layer 4)

Timeline: After Phase 4 gate passes

What happens: Test actual traffic flow across tunnel

Affinity’s Test (from EKS pod)

# Affinity pings a host on your network
kubectl run vpn-test --rm -it --image=alpine -- sh

# Inside pod:
ping -c 10 [YOUR_TEST_IP]  # e.g., 172.16.1.100
# Expected: 0% packet loss, round-trip time ~45-100ms

# Test MTU
ping -c 3 -M do -s 1400 [YOUR_TEST_IP]  # May fail
ping -c 3 -M do -s 1350 [YOUR_TEST_IP]  # Should succeed

Your Confirmation

On your test host, monitor traffic arrival:

# Monitor incoming traffic from Affinity
show session all | match "source:10.0"

# Verify tunnel traffic statistics
show vpn ipsec sa detail | grep -E "bytes|packets"

# Check BGP routes are being used
show routing route bgp | match "169.254"

# Review traffic logs
show log traffic

Gate 5.1: Bidirectional ping succeeds with ≤1% loss; MTU 1350+ working

If traffic doesn’t pass: See Remediation Playbooks → “Traffic Not Passing”

Phase 6: Redundancy & Failover Test (Layer 5) — OPTIONAL

Timeline: Can be deferred to maintenance window

What happens: One tunnel is disabled; verify other handles all traffic

Your action: Continuous ping during test

# Start continuous ping to Affinity test IP (request command syntax)
> ping host [AFFINITY_TEST_IP] count 1000 timeout 1

# Affinity will disable Tunnel 1 on their side
# Expected ping behavior:
# [Normal] ~1ms latency, 0% loss
# [Tunnel 1 DOWN] Brief interruption (1-3 sec)
# [DPD timeout] 10 second delay (Palo Alto default)
# [BGP reconvergence] Another 5-10 seconds
# [Resumed] Ping continues normally through Tunnel 2

# Total disruption: 15-25 seconds

# Monitor tunnel switching
> show vpn ipsec sa
# Should see Tunnel 2 taking all traffic

Gate 6.1: Single tunnel failure does not cause total outage

Phase 7: Operational Sign-Off

Timeline: After all Phase 5 (or Phase 6) gates pass

Action: Complete bilateral sign-off checklist in VPN_E2E_TESTING_PROTOCOL.md Phase 7 section

Palo Alto Verification Checklist: - [ ] show vpn ipsec sa shows both tunnels Established - [ ] show vpn ike sa shows both IKE SAs active - [ ] show routing bgp peers shows neighbors Established - [ ] show routing bgp rib routes shows learned CIDRs - [ ] Data plane ping succeeds (0% loss) - [ ] Failover test completed (if performed) - [ ] Configuration backed up and documented

Once signed: Tunnel is production-ready

📋 Configuration Checklist

Before declaring configuration complete:

IPSec Configuration: - [ ] IKE Crypto Profile created (AES-256, SHA2-256, Group 14, 8-hour lifetime) - [ ] IPSec Crypto Profile created (AES-256, SHA2-256, 1-hour lifetime) - [ ] IKE Gateways created for both tunnels - [ ] IPSec Tunnels created for both tunnels - [ ] DPD enabled (10 seconds) - [ ] PSKs entered correctly (case-sensitive)

Network Configuration: - [ ] Tunnel interfaces configured with correct IPs (169.254.x.x/30) - [ ] Zones created or assigned for tunnel interfaces

Security Policy: - [ ] Security policy created allowing VPN traffic - [ ] Policy positioned before deny-all rules - [ ] Logging enabled on policy

Routing: - [ ] Static routes configured or BGP enabled - [ ] BGP peers configured if using dynamic routing - [ ] Routes to Affinity CIDR blocks present

Verification: - [ ] Both tunnels show UP with Phase 2 SAs - [ ] BGP peers show Established (if using BGP) - [ ] Routes to AWS appearing in routing table - [ ] Ping test to AWS network successful - [ ] Logs show successful tunnel negotiation
