VPN E2E Testing - DevOps Quick Start Guide

Status: ✅ Production Ready Last Updated: March 4, 2026 Audience: Affinity & Peer DevOps Teams

🚀 Quick Overview

This guide provides DevOps teams with the fastest path to: 1. Understand the VPN tunnel testing process 2. Execute E2E verification 3. Troubleshoot common issues 4. Sign off on production readiness

Total Time to Production: ~2 hours (configuration + testing)

📚 Documentation Structure

For Affinity DevOps

Before anything: Read VPN_E2E_TESTING_PROTOCOL.md (Phases 0-1)

Then follow: 1. Phase 0: Pre-deployment checklist (Pulumi) 2. Phase 1: Prepare handoff package using VPN_HANDOFF_TEMPLATE.md 3. Phases 3-7: Follow along with peer (see below)

Tools:

# Monitor tunnel status
./skill-vpn-connectivity --peer <PEER_NAME>

# Full E2E verification
./skill-vpn-e2e-test --peer <PEER_NAME> --e2e

# Layer-specific testing
./skill-vpn-e2e-test --peer Vimenca --layer 3  # BGP only

For Peer DevOps Teams

Step 1: Receive handoff package from Affinity

Step 2: Select your device guide: - Checkpoint R80.10+ → peer-guides/CHECKPOINT_SETUP_GUIDE.md - Fortinet FortiGate → peer-guides/FORTIGATE_SETUP_GUIDE.md - Palo Alto Networks → peer-guides/PALOALTO_SETUP_GUIDE.md - Cisco ASA → peer-guides/CISCO_SETUP_GUIDE.md

Step 3: Follow device guide → Section 4: Step-by-Step Configuration (30-45 min)

Step 4: Follow device guide → Section 8: Joint E2E Testing (Phases 3-7) (30-60 min)

⚡ Fast Path: Testing Checklist

Once device is configured, run this checklist:

Phase 3: Tunnel UP (5-10 minutes)

Affinity runs:

./skill-vpn-connectivity --peer <PEER_NAME>
# Expected: Both tunnels show "UP"

Peer runs:

# Checkpoint
fw stat -sc | grep Tunnel
# Expected: Both tunnels show "Established"

# Fortigate
diagnose vpn tunnel list | grep -E "Phase|State"
# Expected: Phase 1 & 2 both ESTABLISHED

# Palo Alto
show vpn ipsec sa | grep -E "tunnel:|state"
# Expected: Both tunnels show "Established"

# Cisco
show crypto ikev2 sa
show crypto ipsec sa
# Expected: IKE SAs ESTABLISHED, IPSec SAs active

Gate 3.1: Both tunnels UP on both sides? ✅ Proceed to Phase 4

Phase 4: BGP Routes Learned (5-10 minutes)

Affinity runs:

./skill-vpn-e2e-test --peer <PEER_NAME> --layer 3
# Expected: Routes from peer CIDR found in TGW route table

Peer runs:

# Checkpoint
netstat -rn | grep 169.254
# Expected: Routes to Affinity CIDRs via tunnel inside IPs

# Fortigate
get router bgp summary
# Expected: Neighbors show "Established" with route count > 0

# Palo Alto
show routing bgp peers
# Expected: Neighbors show "Established"

# Cisco
show bgp summary
# Expected: Neighbors show "Established" and prefix count > 0

Gate 4.1: Routes learned on both sides? ✅ Proceed to Phase 5

Phase 5: Data Plane Test (5-10 minutes)

Affinity runs:

# From EKS pod or EC2 instance
ping -c 10 <PEER_TEST_IP>    # e.g., 172.16.1.100
# Expected: 0% packet loss, typical latency 45-100ms

# Test MTU
ping -c 3 -M do -s 1350 <PEER_TEST_IP>
# Expected: All packets succeed

Peer confirms:

# Monitor traffic arrival
tcpdump -i any "src 10.0"    # Monitor for Affinity CIDR
# Expected: ICMP echo-request packets arriving

# Verify tunnel is in use
# Checkpoint: fw stat -sc | grep bytes
# Fortigate: diagnose vpn ipsec sa list | grep bytes
# Palo Alto: show vpn ipsec sa detail | grep bytes
# Cisco: show crypto ipsec sa detail

Gate 5.1: Bidirectional ping succeeds with 0% loss? ✅ Proceed to Sign-Off

Phase 6: Failover Test (Optional, 10-15 minutes)

# Peer: Start continuous ping
ping -i 1 <AFFINITY_TEST_IP> | tee failover.log

# Affinity: Disable Tunnel 1 (AWS console)
# Monitor: Peer observes brief interruption (~15-90 seconds)

# Affinity: Re-enable Tunnel 1
# Verify: Ping resumes, both tunnels return to UP

# Gate 6.1: Single tunnel failure doesn't cause total loss? ✅

🚨 Troubleshooting Quick Links

Tunnel Stays DOWN? - Verify PSK is exactly correct (case-sensitive, no spaces) - Check firewall allows UDP 500, 4500 outbound to tunnel endpoints - Verify encryption settings: IKEv2, AES-256, SHA2-256 - → See VPN_E2E_TESTING_PROTOCOL.md Playbook 1

BGP Routes Not Appearing? - Verify tunnels are UP first - Check BGP neighbors show as Established - Verify neighbor IPs = 169.254.x.1 (inside tunnel IPs) - Verify AWS ASN = 64512 - → See VPN_E2E_TESTING_PROTOCOL.md Playbook 2

Traffic Not Passing? - Verify tunnels UP and routes learned - Check security policies/ACLs allow traffic - Verify no NAT masking the source IP - Test MTU: ping -M do -s 1350 - → See VPN_E2E_TESTING_PROTOCOL.md Playbook 3

📋 Sign-Off Checklist

Once all phases pass, complete the sign-off:

Both teams verify: - [ ] Tunnels UP (both sides) - [ ] BGP routes learned (both sides) - [ ] Data plane ping 0% loss - [ ] MTU ≥1350 bytes working - [ ] Failover tested (or scheduled)

Both teams sign: Use sign-off sheet in VPN_E2E_TESTING_PROTOCOL.md Phase 7

Result: Tunnel is production-ready ✅

🔧 Key Commands Reference

Affinity Commands

# Quick status
./skill-vpn-connectivity

# Deep analysis
./skill-vpn-connectivity --deep

# E2E test
./skill-vpn-e2e-test --peer <NAME> --e2e

# Layer-specific test
./skill-vpn-e2e-test --peer <NAME> --layer 2  # Tunnel only
./skill-vpn-e2e-test --peer <NAME> --layer 3  # BGP only
./skill-vpn-e2e-test --peer <NAME> --layer 4  # Data plane

# AWS CLI commands
aws ec2 describe-vpn-connections \
  --filters "Name=tag:Name,Values=<PEER>" \
  --query 'VpnConnections[0].VgwTelemetry[*].[OutsideIpAddress,Status.TunnelStatus]'

# Check route table
aws ec2 describe-transit-gateway-routes \
  --transit-gateway-route-table-id tgw-rtb-079e9cb450e5355e6 \
  --query "Routes[?DestinationCidrBlock=='<PEER_CIDR>']"

Device-Specific Commands

Checkpoint:

fw stat -sc                    # Tunnel summary
vpn tunnel get -x 0            # Tunnel 1 details
netstat -rn | grep 169.254     # BGP routes

Fortigate:

diagnose vpn tunnel list       # Tunnel summary
get router bgp summary         # BGP neighbors
diagnose vpn ipsec sa list     # IPSec details

Palo Alto:

show vpn ipsec sa              # Tunnel summary
show routing bgp peers         # BGP neighbors
show routing bgp rib routes    # Learned routes

Cisco:

show crypto ikev2 sa           # IKE summary
show crypto ipsec sa           # IPSec details
show bgp summary               # BGP neighbors
show bgp ipv4 unicast summary  # Learned routes

🎯 Success Criteria

Tunnel is Production-Ready When:

✅ Both tunnels reach UP state within 30 seconds of device config

✅ BGP neighbors show Established with >0 routes within 1 minute

✅ Ping from Affinity to peer succeeds with 0% packet loss

✅ Ping with 1350-byte MTU succeeds (confirms path MTU)

✅ Failover: Single tunnel DOWN does not cause total loss

✅ Both teams sign operational readiness sign-off sheet

🔑 Key Insights

  1. AWS VPN is responder-only — Peer device initiates; AWS responds
  2. Tunnels should reach UP in 5-30 seconds — Check PSK, encryption, firewall
  3. BGP converges in 5-15 seconds — Wait and recheck
  4. DPD timeout affects failover — Checkpoint: 30s, Others: 10s
  5. MTU is critical — Test 1350+ bytes; IPSec adds 50-70 byte overhead
