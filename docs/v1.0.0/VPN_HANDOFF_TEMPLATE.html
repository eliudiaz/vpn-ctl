🚀 Key Technical Notes

AWS VPN is Responder-Only

CRITICAL: AWS does NOT initiate IPSec. Your device MUST initiate IKE (Main Mode or Aggressive Mode).

What this means: 1. Configure tunnel on your device 2. Enable/activate VPN 3. Your device sends IKE_SA_INIT to AWS endpoint 4. AWS responds and completes negotiation 5. Tunnels come UP within 5-30 seconds

If tunnels don’t come UP after 30 seconds: - Verify PSK is exactly correct (case-sensitive) - Verify firewall allows UDP 500, 4500 outbound to tunnel endpoints - Check encryption settings match exactly - Enable debug logging on device and inspect IKE messages

Dual Active Tunnels (Not Redundant)

Both tunnels are active and carry traffic (not primary/secondary).

Implication: - Traffic load-balances across both tunnels - If one tunnel fails, the other carries all traffic - Both must be configured for full redundancy

Failover behavior: - DPD detects tunnel failure: 10-30 seconds (device-dependent) - BGP reconvergence: 5-10 seconds - Total recovery time: 15-90 seconds - Expected total outage: ≤2 minutes during single-tunnel failure

MTU Configuration

IPSec adds ~50-70 bytes of header overhead. Standard Ethernet MTU is 1500 bytes.

Recommended: Configure tunnel path MTU to 1350-1370 bytes to avoid fragmentation.

How to test (after tunnel UP):

ping -M do -s 1350 [AFFINITY_TEST_IP]
# Should succeed with 100% success rate

If failures at 1350: - Set device MTU to 1300-1320 - Or enable path MTU discovery on device - Or allow IP fragmentation on tunnel interface
